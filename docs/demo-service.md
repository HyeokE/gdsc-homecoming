# 브라우저 데모 서비스

이 구현은 행사 명단·Firebase 발권 API를 호출하지 않는다. Firebase 초기 설정과 deny-all 규칙은 유지한다. 실제 운영에는 서버 명단 확인, 신뢰할 수 있는 세션 및 배정·재발급 트랜잭션이 필요하다.

## 사용

`demo@gdg.example`, `member@gdg.example`, `guest@gdg.example`만 테스트 참가자로 인정한다. 실제 개인 이메일은 등록되지 않았다. `/` → `/email` → `/nickname` → `/departure` → 확인 → `/issuer` → 탑승권 보기 → `/ticket`이 현재 앱 경로다. 발권기는 네 번째 화면의 하위 상태이며 독립 제품 화면을 추가한 것이 아니다.

표시명은 공백만 제거한 입력을 보존한다. 대소문자·한글·이모지를 제한하거나 실명으로 인증하지 않는다. 알파벳 대문자 A–Z와 소문자 a–z, 숫자 0–9는 정순 휠을 사용한다. 결합문자/이모지 등 지원하지 않는 grapheme은 하나의 패널로 그대로 표시한다. 긴 이름은 글자를 지우지 않아 공개 목표 6~8초를 넘길 수 있다.

## 보존과 복구

- `localStorage`의 `gdg-homecoming-demo-v1`에 버전·데모 이메일·최소 티켓 자료·마지막 작업 식별자를 저장한다. 이메일은 티켓 표시 모델이나 PNG에 포함하지 않는다.
- `sessionStorage`의 `gdg-demo-participant`는 현재 탭의 확인한 데모 이메일만 보존한다. 새로고침은 저장된 티켓을 복원하며 전광판/발권기 실행을 복원하거나 재발급하지 않는다.
- 기존 이메일 확인은 닉네임·새 추첨을 건너뛰고 티켓으로 간다. 직접 주소는 참가 확인/저장 결과가 없으면 입력 단계로 이동한다. 발권기 직접 진입은 확인 전 전광판으로 돌아간다.
- 중복 발급은 기존 결과를 반환한다. 재발급은 같은 작업 식별자 재시도에 같은 결과를 반환하고, 다른 작업의 두 번째 재발급은 거부한다. 응답 불확실성은 저장 결과를 조회하고 그 결과를 사용한다.
- 재발급은 직전 국가를 제외하고 gate/승객명/id를 유지한다. 확정 실패·저장 실패는 기존 결과와 기회를 유지한다. 집계/이미지 실패는 티켓과 별도로 재시도한다.
- 손상된 저장 자료는 오류로 보고하며 자동 삭제하지 않는다. 테스트 자료 초기화는 개발자 도구에서 위 두 키만 명시적으로 지우는 방식이며 제품에 개인정보 목록/관리자 기능을 추가하지 않았다.

## 집계와 제한

데모 집계는 이 브라우저의 저장 결과를 읽으며 본인을 포함한다. 국가별 4명과 행사 60명 상한을 별도로 모델링한다. 재발급은 저장 스냅샷 내 목적지 변경 한 번으로 이전 자리를 반환한다. 현재 20×4자리/60명 모델에서 정상 자료가 모두 찬 다른 국가 없이 남는 상황은 발생하지 않지만 서비스는 대안 없음 오류를 구분한다. 브라우저 간·탭 간 경쟁 및 서버 원자성은 보장하지 않는다. A03은 행사 좌석 예약이 아닌 데모 gate fixture다.

20개국/대표도시·공항·키워드는 원본 기획 표를 사용한다. `destinations.ts`의 짧은 소개는 해당 키워드에서 작성한 **창작 제안**이며 사용자 승인된 관광 사실이나 문구로 취급하지 않는다.

## PNG 저장

[html-to-image 공식 사용법](https://github.com/bubkoo/html-to-image)에 따라 티켓만 포함한 DOM을 PNG로 캡처한다. 3배 pixel ratio로 가로형 티켓을 저장하고 파일명은 티켓 id의 안전한 문자만 사용한다. 이메일·화면 설명·버튼은 캡처 DOM 밖에 있다. 성공은 브라우저 다운로드 요청을 의미하며 사진첩 저장 완료를 주장하지 않는다. 이미지 생성 실패 시 결과를 유지하고 다시 시도한다. SVG foreignObject/canvas 기반이므로 실제 모바일 Safari/기기별 다운로드 검증은 별도다.

## 개발 시나리오

`createDemoTicketService({ storage, emails?, random?, now? })`로 격리 저장과 결정적 추첨을 주입할 수 있다. `failNext(operation, kind)`는 Storybook/테스트 전용이고 제품 UI에 노출하지 않는다. connection은 commit 전, issue/reissue의 uncertain은 commit 후 응답 실패를 재현한다. 실제 네트워크 timeout이나 서버 트랜잭션을 수행한 것은 아니다.

## 기존 연출 프리뷰

`/preview/departure`와 `/preview/issuer`는 main의 별도 라우트 트리에서 `PreviewApp`만 마운트한다. 참가 확인·저장 결과 복원이 개입하지 않는 JASON JEONG/JAPAN/NRT/A03 고정 샘플이다. 확인 전 issuer 직접 진입은 departure로 돌아가고, 확인/가로 조건/단일 출력은 제품과 같은 hook을 소비한다. 완료 후 다시 보기는 새 runId로 샘플만 재생하며 데모 티켓 저장을 변경하지 않는다.
