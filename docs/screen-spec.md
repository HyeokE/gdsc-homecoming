## 4. 추첨 전광판·출력 연출 화면

### 목적과 진입

- [확정] 최초 발급 또는 재발급의 결과를 공항 전광판과 출력 연출로 공개한다.
- [확정] 최초 발급은 3번 제출, 재발급은 5번의 확인 절차에서 진입한다. 저장 완료가 연출의 선행 조건이다.

### 내용·동작·전환

- [제안] 저장 처리 중에는 “탑승권을 준비하고 있어요.”를 표시하며 확정되지 않은 목적지를 결과처럼 보여주지 않는다.
- [확정/사용자 최신 수정] 중앙의 **당신의 국가는** 문구 아래 이미 있는 국가 패널의 상하 반부가 중앙 힌지를 축으로 실제 회전하는 split-flap 모션으로 국가명을 공개한다. 글자는 정해진 A→B→…→Z→A 순서, 숫자는 0→1→…→9→0 순서로 한 바퀴 이상 돈 뒤 목표에 정착한다. 매 flip마다 current와 next 문자의 위·아래 반부가 실제 판을 통해 교체된다. 랜덤 문자 금지는 이 순서 있는 문자 휠을 금지하는 의미가 아니며, 빈 판에서 목표로 한 번만 바뀌는 방식으로 대체하지 않는다. 국가명 정착 후 Motion layout/shared-layout 전환으로 카드가 등장하고 승객명·국가·대표 도시·공항 코드·게이트 정보 패널을 가로 stagger로 공개한다.
- [확정/사용자 최신 수정] 공개 연출은 약 **7초**(6~8초 범위)이며 완료 후 **확인했어요**를 기다린다. 이전 자동 출력·자동 화면 전환은 폐기한다. 저장 요청 대기 시간과 공개 연출 시간은 구분한다.
- [현재 프리뷰 타이밍] 국가 휠은 처음부터 시작하고 실제 최종 정착 2.82초 뒤 한국어 국가 라벨을 표시한다. 280ms 뒤 카드 확장(3.10초), 650ms 레이아웃 전환이 끝난 3.75초부터 정보 휠을 시작한다. 마지막 공항 패널은 6.91초에 정착하고 확인은 7.15초에 제공한다. 전체 계획은 샘플 문자열에서 계산하며 중복된 고정 phase 시각을 두지 않는다. Motion 완료 이벤트가 업무 상태를 결정하지 않는다.
- [현재 프리뷰 휠 정책] A-Z와 0-9는 최소 한 바퀴 후 목표 인덱스까지 순차 진행한다(A도 전체 순환 후 정착). 공백과 현재 샘플의 기호는 정적으로 보존한다. 각 flip은 기본 60ms, 최종 여섯 flip은 110ms로 감속하며 좌우 시작 간격은 30ms다. 알고리즘과 판 애니메이션은 같은 duration을 소비한다. 늦은 프레임은 절대 시작 시각에서 순환 위치를 계산하고 새 프리뷰의 이전 step/timer를 재사용하지 않는다. reduced-motion은 목표를 즉시 표시하지만 명시적 확인을 유지한다. 순환은 표현용이며 새 국가 배정이 아니다.
- [확정/사용자 최신 수정] **확인했어요** 이후 상단 발권기 표현으로 전환한다. 세로 폰에서 즉시 가로형 보딩패스 출력을 시작한다. 상단 발권기의 출력구에서 티켓이 위에서 아래로 내려온다. 티켓 자체는 너비가 높이보다 긴 가로 비율이며 세로 모바일 컨테이너 안에 전체가 보이도록 배치한다. 정확한 비율을 고정하지 않으며 500px 상한을 유지한다. 이전 가로 회전 요구는 이 정책으로 대체한다.

- [확정] 소리 활성화 상태에서만 전광판 효과음·발급 완료음을 재생한다.
- [확정/사용자 최신 수정] 동작 줄이기에서는 긴 공개·출력 연출을 생략한다. **확인했어요**는 유지하며, 확인 후 출력 완료를 즉시 표시한다.
- [제안] 저장 이후 연출이 끝나지 않아도 **탑승권 바로 보기**로 결과에 접근할 수 있게 한다. 연출 생략은 재추첨을 발생시키지 않는다.

- [제안/디자인 검토] 화면 순서: 발급 완료 안내 → 티켓·확대 → 저장 CTA → 소개·키워드 3개·인원 → 재발급. 좁은 화면에서는 티켓 밖에도 목적지·승객명 텍스트를 보완한다.
- [확정] 가로형 고해상도 이미지로 저장한다. 버튼과 패션 힌트는 저장 이미지에서 제외한다.
- [미정] 이미지 해상도·파일 형식·모바일 브라우저별 저장 방식. 국가 소개 최종 문구와 패션 키워드는 원본 초안을 검토해 확정한다.
- [미정] QR 내용·연결·공유 이미지에서의 동작. 확정 전 작동하는 QR이나 임의 목적지를 만들지 않는다. 확정 후 자기 휴대폰에서 터치 접근도 제공해야 한다.

### 상태·재시도·중단 복원

- [확정] 저장 중 / 완료 / 실패·재시도, 재발급 미사용 / 사용 완료 상태를 구분한다.
- [제안] 저장 진행 중 반복 클릭을 방지한다. 브라우저의 다운로드·공유 호출 성공만으로 사진첩 저장 완료를 단정하지 않고 확인 가능한 결과에 맞는 문구를 사용한다.
- [제안] 이미지 생성 실패는 티켓을 유지하고 저장 재시도를 제공한다. 국가 소개·인원수 조회 실패도 기존 티켓을 제거하지 않는다.
- [제안] 동행 인원 로딩·조회 실패는 “확인 중”·재시도로 구분하며 임의로 0명이나 이전 값을 현재 값처럼 표시하지 않는다.
- [제안/백엔드 검토] 인원수는 조회 시점의 자료이며 이후 변할 수 있다. 인원 조회 실패는 발급 실패와 분리하고 인원 영역만 재시도한다. 타인의 티켓 정보는 노출하지 않는다.
- [원본 초안] 본인만 있으면 “첫 번째 탑승객이에요. 곧 함께 떠날 동행이 생길 거예요.”, 여러 명이면 “나를 포함해 3명이 도쿄행 탑승권을 받았어요.” 같은 문구 사용 가능.
- [확정] 재접속 시 저장된 티켓과 재발급 상태를 복원한다.
- [미정] 동행 인원 갱신 시점·주기와 소개 콘텐츠 미등록 시 안내 문구.

### 접근성과 완료기준

- [제안] 축소 티켓을 이미지로만 읽게 하지 않고 승객명·목적지·행사 정보를 텍스트로 제공한다. 확대 진입 버튼의 목적을 명확히 표시한다.
- [확정 기준] 화면 및 이미지의 행사·승객·배정 정보가 저장된 결과와 일치한다. 이미지에 이메일·버튼·패션 힌트가 들어가지 않는다.
- [확정 기준] 재발급을 사용한 참가자는 추가 변경이 불가능하다. 다른 참가자의 이름을 공개하지 않는다.
- [제안] 세로·가로의 동일 500px 컨테이너 안에서 전체 티켓 보기·확대·저장에 접근할 수 있다.

## 모달과 공통 처리 상태 [구성 제안]

### 재발급 확인 모달

- [확정] 티켓 화면에서 재발급 확인 후 새 국가를 배정한다. 직전 국가를 제외한 여유 국가 중에서 선택한다.
- [원본 초안] “재발급하면 현재 목적지로 돌아올 수 없어요. 새 여행지를 뽑을까요?”
- [제안/디자인 검토] 현재 국가를 함께 표시하여 무엇을 바꾸는지 명확히 한다. 사용 완료와 변경 가능한 국가 없음은 별개 상태로 안내한다.
- [제안] **현재 탑승권 유지** / **새 여행지로 재발급**. 취소는 배정·기회에 영향이 없다. 확인하면 4번의 재발급 처리 상태로 전환한다.
- [확정] 새 배정·이전 자리 반환·기회 차감은 원자 처리한다. 실패 시 기존 티켓과 기회를 유지하며, 게이트·재발급 전후 소리 설정은 유지한다.
- [확정] 변경 가능한 국가 없음 상태를 처리한다. [제안] 기존 티켓·기회를 유지하고 현 상태 유지 또는 재시도 안내를 제공한다.
- [제안] 처리 중 화면을 닫거나 응답이 끊겨도 취소 완료로 단정하지 않는다. 저장 결과를 확인해 이전 또는 새 티켓과 실제 기회를 복원한다.
- [제안/백엔드 검토] 다른 탭에서 재발급이 완료된 경우 최신 티켓과 기회 소진 상태를 복원한다. 변경 가능한 국가가 없으면 기존 티켓·기회를 유지한다.
- [미정] 재발급 종료 시점과 종료 시 버튼·안내 정책.

### 티켓 확대 모달

- [확정] 크게 보기 기능을 제공한다. [제안] 동일 모바일 컨테이너 안의 모달로 티켓을 확대하고 필요한 경우 내부 스크롤을 제공한다.
- [제안] 명시적인 **닫기** 버튼을 제공하고 원래 화면으로 돌아간다. 확대는 배정·저장·재발급 상태를 변경하지 않는다.
- [제안] 닫을 때 실행 버튼으로 초점을 돌리고, 모달이 열려 있는 동안 배경의 조작·읽기 접근을 제한한다. 확대된 정보는 스크린리더로도 읽을 수 있어야 한다.
- [미정] 확대 비율·내부 이동 방식. 가로 회전 후에도 max-width 500px 제약을 유지한다.

### 공통 상태 기준

- [제안] 요청 중에는 작업 이름과 진행 상태를 알리고 반복 제출을 막는다. 요청 실패·명단 없음·결과 없음·복원 실패를 서로 구분한다.
- [확정] 네트워크 오류는 기존 결과를 보존한다. [제안] 재시도는 해당 작업 범위로 제한하고 결과가 이미 저장되었는지 먼저 확인한다.
- [제안] 새로고침·뒤로 가기·중복 탭·응답 지연 상황에서도 화면 표시만으로 기회가 차감되거나 결과가 바뀌지 않아야 한다.
- [제안] 모달은 제목, 초점 관리, 닫기 버튼을 제공한다. 처리 요청을 보낸 이후 닫기·뒤로 가기의 허용 UX는 실제 처리 상태와 함께 결정한다.

## 검토 진행

### 역할 분담 [사용자 확정]

- 기획자: 화면 상세 기획과 확정·제안·미정 구분, 검토 의견 통합.
- 디자이너: UI 설계와 표현 컴포넌트 마크업·스타일·시각 모션 구현.
- 프론트엔드: 라우팅·상태 관리·입력 검증·API 연동·저장 기능 및 통합 검증.
- 백엔드: 서버 명단 검증·DB·추첨 및 재발급 원자성.
- 매니저: 계획·작업 배정·검토·통합·상태 보고. 이번 문서 수정은 구현 작업과 별개이며, 현재 화면 구현 범위는 상단의 샘플 결과 프리뷰 안내를 따른다.

### 검토 순서

- 1번 입장 화면부터 내용·CTA·정보 배치를 검토하고, 이후 2 → 3 → 4 → 5번 순으로 구체화한다.
- 디자이너·백엔드 검토 의견은 사실·제약·제안으로 구분해 반영한다. 검토자 제안만으로 사용자 미정 정책을 확정으로 승격하지 않는다.
- 이 문서의 완료기준은 향후 구현 검증을 위한 초안이며 현재 기능이 구현·검증되었다는 뜻이 아니다.

## 현재 샘플 프리뷰 라우트

React Router DOM의 BrowserRouter/Routes를 사용한다. 현재 구현은 최종 제품 5개 페이지가 아닌 고정 샘플 연출 확인용 경로다.

- `/`: 샘플 미리보기 진입.
- `/preview/departure`: 고정 샘플의 국가·정보 공개와 **확인했어요** 대기. 직접 접속·새로고침은 같은 샘플 공개를 처음부터 시작한다.
- `/preview/issuer`: 해당 프리뷰 세션에서 결과를 확인한 뒤에만 진입한다. 직접 접속·새로고침으로 확인 상태가 없으면 `/preview/departure`로 이동하므로 명시적 확인을 우회하지 않는다.

프리뷰 세션 상태는 두 하위 경로를 오가는 동안 유지하며, URL만으로 국가 배정이나 출력 완료를 추론하지 않는다. 확인과 다시 보기는 현재 하위 경로를 replace해 뒤로 가기에서 이미 확인한 단계를 중복 실행하지 않는다. `/`로 돌아가면 세션이 종료되고 타이머와 구독이 정리된다. 앞으로 가기로 다시 공개 경로에 들어가면 새로운 샘플 프리뷰 세션을 시작한다. 알 수 없는 경로는 `/`로 이동한다. 이 동작은 실제 결과 저장·복원을 구현한 것이 아니다.
